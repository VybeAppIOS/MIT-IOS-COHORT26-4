## 2. Team rules
- Branches: `<initial>/<task-id>-<short-name>`, e.g. `t/sc-d1-discover-map`. Short-lived.
- Nothing is pushed to main. Everything goes through a pull request. Squash-merge.
- PR: about 300 lines max. Title "<task id>: what it does". Description: how to test, screenshot, which AI,
  pasted `check.sh` output, and "In my own words" (3 to 5 sentences).
- Lohitaksh reviews every PR and asks two "why" questions.
- Done = `AGENTS.md` section 6 (builds, runs, loading/empty/error, Theme tokens, previews, ViewModel test,
  author can explain every line).
- Stand-up 9:30 daily. Merge windows 13:00 and 19:00. Push unfinished work by 21:00.
- Never paste passwords, keys or personal data into any AI.
- Start each AI task with: "Read AGENTS.md and the task <ID> in docs/tasks/. Plan only; wait for my OK."

## 3. The work: a pool of tasks
- Index with sizes, dependencies and the "start now" list: **`docs/TASKS.md`** (generated by
  `python3 scripts/build_task_index.py`, which also checks that every IA screen has a task).
- Details of each task (read first, what to build, files, done-when): `docs/tasks/*.md`.
- Before your first task: `docs/START-HERE.md`.
- GitHub issues: one per task (script X-6); claim a task by assigning yourself.

**Rules to keep the plan honest**
1. At most **1 task in progress per person**; an unfinished task is reviewed or handed over after 2 days.
2. **Measure every Friday:** tasks merged, days used, estimate vs real; update `docs/TASKS.md` totals.
3. **Stub-heavy screens (chat, feed) are written against the protocol, not the stub's quirks**, and the
   shared contract test must pass for stub and remote, so M4 is a swap, not a rewrite.
4. A task with no GitHub issue and no named owner does not start.
5. Every Monday: triage tester feedback and re-read `docs/OPEN-QUESTIONS.md` for blockers.
